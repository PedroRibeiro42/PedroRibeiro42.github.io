1. Understanding Binary Trees
(the goal of this exercise is for you to understand what a binary tree is and some of the orders in which we could traverse its nodes)

  1. Your first binary tree

    One way of describing a tree is to use one of the following representations:

    • preorder (DFS): root, followed by the preorder representation of the left subtree, followed by the preorder representation of the right subtree.
    • inorder (DFS): inorder representation of the left subtree, followed by the root, followed by the inorder representation of the right subtree.
    • postorder (DFS): postorder representation of the left subtree, followed by the postorder representation of the right subtree, followed by the root.
    • breadth-first (BFS): nodes in increasing order of depth (from top to bottom) and on the same level from left to right.

    Consider for instance the tree of the following figure:

    Using the 4 representations given before, the tree would be described as:

    • preorder: 5 1 8 6 7 2
    • inorder: 8 1 6 5 2 7
    • postorder: 8 6 1 2 7 5
    • breadth-first: 5 1 7 8 6 2
  2. Understanding traversal order

    To make sure you understood, write down the four representations given (preorder, inorder, postorder, breadth-first) but for the following tree:

    Solution

    - preorder: 6 8 4 3 5 1 7

    - inorder: 8 4 6 1 5 3 7

    - postorder: 4 8 1 5 7 3 6

    - breadth-first: 6 8 3 4 5 7 1

2. A binary tree implementation
(the goal of this exercise is for you to understand a basic implementation of binary trees that uses templates)

  1. Binary Trees - the code

    Compile the code. The whole BTree<T> class is contained in the .h file, so you just need to compile testBTrees.cpp (make sure they are in the same directory, so that the line #include "binaryTree.h" knows where to find the file it wants to include). If you are on a shell, you could for instance run g++ -std=c++17 -Wall -o testBTrees testBTrees.cpp to obtain an executable with the name testBTrees.

  2. A first test

    Download the file input.txt containing a line with 5 1 8 N N 6 N N 7 2 N N N. This is the serialization of the tree in the following figure: its preorder representation with N explicitly representing the nullptr nodes (as seen in the lectures, this is enough to rebuild the tree, while the preorder alone is not):


    (the two representations in this figure refer to the same tree)

    Now run the test code you compiled giving as input the file you downloaded (equivalent to writing its contents as the input):

    ./testBTrees < input.txt

    You should obtain the following as the output:

    Notice that the PreOrder and DFS lines are equal, and this is not a mistake: the DFS with a stack (printDFS()) visits the nodes in the same order as the recursive PreOrder (see slides 28 and 29).

Before you start: adding methods to the class

In exercises 3 to 9 you will be adding methods to the BTree<T> class (only the challenge is different). Add the requested method at the end of the class (but before the closing bracket), together with any recursive helper it needs, just like numberNodes() and its helper. You only need to submit the binaryTree.h file!

If you want to test the method on your computer, you can copy the tester code from the problem statement (use the Copy button above it) to a file on your computer, compile it and use the example input to see if the results are as expected (note how easy it is to add new inputs, if you want to make further tests - you can simply give new trees with their serialization, as shown in exercise 2).

If your program crashes with Segmentation fault (often a missing nullptr check in a recursive method), compile it again with g++ -std=c++17 -Wall -g -fsanitize=address ... and run it: the error message will then show the method and the line where the crash happened. (This works on Linux and macOS; it is not available with MinGW on Windows.)

Two things to keep in mind:

  • Your method should work for any type T. In problems AED039 to AED042 the tests also include trees of strings, so do not assume the values are integers (AED043 to AED045 only use trees of integers, as their statements say).
  • Be consistent with const. Methods that do not change the tree should be const (see slide 13), and the problem statements say so when this applies. If your main method is const (like numberNodes() const), the helper it calls must also be const. Otherwise the compiler gives an error such as passing 'const BTree<int>' as 'this' argument discards qualifiers.

5. Processing Paths


For this exercise you will be solving the problem [AED041] Tree Paths.
Desired time complexity: \(\mathcal{O}(|s|)\) (where |s| is the length of the path, which is at most the height of the tree: you only need to visit the nodes on the path, not the whole tree)

Notice that the method returns a reference (T &) to the value stored in the node. This means it can also be used to change the tree: in the example of the problem statement, t.path("LR") = 42; replaces the value 5 by 42. This is why path is not declared const, unlike the other methods you write this week: it gives access that allows changing the tree.

Hints

- You do not even need recursion: start with a pointer to the root and, for each character of s, move to the left or to the right child. At the end, return the value of the node you reached

- If you prefer recursion, besides the current node your helper method could have as arguments the path string s and the integer position pos where you are in the path. Looking at s[pos] you decide if you go to the left or to the right, calling the same method for that child... but with the position incremented!

- In both cases, do not forget the special path "_", which represents the root
